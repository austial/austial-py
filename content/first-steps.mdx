# First Steps

In this section you'll install the Austial CLI, scaffold a new project, and
get it running with auto-reload. Austial requires **Python 3.11+** and uses
[uv](https://github.com/astral-sh/uv) for dependency management.

## Installation

<Tabs items={["uv", "pipx", "pip"]}>
  <Tabs.Tab>
    ```bash
    uv tool install austial
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```bash
    pipx install austial
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```bash
    pip install austial
    ```
  </Tabs.Tab>
</Tabs>

This installs the `austial` console script and the framework.

### Packages and extras

`austial` pulls in five distributions, and every module keeps its `austial.<name>` import path:

| Distribution | Modules |
|---|---|
| `austial-core` | `common`, `core`, `config`, `testing`, `events`, `cache`, `schedule`, `jobs`, `cqrs`, `http`, `i18n`, `storage`, `terminus`, `commander`, `websockets`, `graphql`, `openapi` |
| `austial-microservices` | `microservices` |
| `austial-orm` | `orm`, `migrations`, `mongo`, `prisma`, `audit`, `tenancy` |
| `austial-auth` | `auth`, `authz`, `security` |
| `austial-cli` | the `austial` command |

Optional libraries are extras, installed with `pip install 'austial[redis,socketio]'` (or the distribution's own extra): `strawberry` (GraphQL),
`socketio`, `lambda` (`austial-core`); `redis`, `nats`, `kafka`, `mqtt`, `rabbitmq`, `grpc`, `grpc-proto` (`austial-microservices`); and `pymongo` for MongoDB (`austial-orm`).

<Callout type="info">
  **`austial: command not found`?** The folder these tools install into is not
  on your `PATH` yet. This is common when uv comes from Homebrew, and uv only
  warns about it the first time you install.

  - **uv:** run `uv tool update-shell`, then open a new terminal window.
  - **pipx:** run `pipx ensurepath`, then open a new terminal window.

  To skip the install and run the CLI once, use `uvx austial new my-app`.
</Callout>

## Scaffolding a new project

```bash
austial new my-app
cd my-app
uv sync
cp .env.example .env
uv run austial serve
```

`austial new` scaffolds a small "hello world" app, running on
`http://localhost:8000` with auto-reload, exposing:

- `GET /` — a root health-check style greeting
- `GET /health` — a public Terminus-style health check
- `GET /health/protected` — the same check, gated behind an `ApiKeyGuard`
- `/docs` — FastAPI's Swagger UI, free from FastAPI since every route is
  registered as a real `APIRouter`

## Install the Austial plugin and skills

<Callout type="info">
  **Recommended if you build with an AI coding tool.** Install the Austial
  plugin for [Claude Code](https://claude.com/claude-code) *before* you write
  your first feature. It teaches the agent the framework's rules and the
  recommended design patterns, so it generates idiomatic Austial code instead
  of hand-rolling FastAPI routers.
</Callout>

Run this once inside Claude Code:

```text
/plugin marketplace add austial/austial-py
/plugin install austial@austial
```

That installs the skills below. They load on their own when your project
imports `austial`, or you can call them directly:

| Skill | Command | Use it to |
|---|---|---|
| `austial-framework` | automatic | Keep the agent on the framework's mental model, import map and do/don't list |
| `austial:build-app` | `/austial:build-app a bookstore API with users and orders` | Go from an idea to a scaffolded, tested app that follows the recommended module layout |
| `austial:add-feature` | `/austial:add-feature websocket chat` | Add one capability (auth, tenancy, jobs, GraphQL, cache, ...) the recommended way |
| `austial:review-app` | `/austial:review-app` | Check your changes against the [production checklist](/ai/production) |

Not using Claude Code? `austial new` already writes an `AGENTS.md` for every
other tool, and [Tool Setup](/ai/setup) links it for existing projects. See the
[Claude Code plugin](/ai/claude-plugin) page for the full list, updating, and a
sample session.

## Project structure

```
my-app/
├── pyproject.toml          # dependencies=["austial>=..."], dev extras, ruff/mypy config
├── .env.example             # PORT=8000 / API_KEY=changeme
├── AGENTS.md                 # rules for AI coding tools (CLAUDE.md, GEMINI.md, ... are symlinks to it)
├── .pre-commit-config.yaml   # ruff + mypy + pytest hooks, same as this framework's own repo
├── src/
│   ├── main.py                # AustialFactory.create(AppModule) -> app.listen(8000)
│   ├── app/
│   │   ├── app_module.py        # root @Module(...): imports, controllers, providers, configure()
│   │   ├── app_controller.py      # GET / -> {"message": "Hello from my-app, built with Austial!"}
│   │   └── app_service.py
│   ├── modules/                   # one folder per feature
│   │   └── health/
│   │       ├── health_module.py
│   │       ├── health_controller.py    # GET /health, GET /health/protected
│   │       ├── health_service.py        # HealthCheckService + MemoryHealthIndicator
│   │       └── health_dto.py
│   ├── shared/                    # used by more than one module
│   │   ├── guards/api_key_guard.py    # ApiKeyGuard(CanActivate)
│   │   └── services/  pipes/  interceptors/  filters/  decorators/  dto/    # empty, ready for your code
│   └── templates/                 # non-Python assets
│       └── email/
└── tests/
    ├── unit/health_service_spec.py
    └── e2e/app_e2e_spec.py
```

The layout is modular: each folder under `src/` has one job, so a project can grow from this starting point without being
reorganised. File names use underscore suffixes (see [the note on file names](/#a-note-on-file-names)), and imports are
absolute from the project root (`from src.modules.health.health_module import HealthModule`).

### Where things go

| Folder | Holds | Create it with |
|---|---|---|
| `src/app/` | The root module, which imports every feature module, plus the app-level controller and service | `austial new` |
| `src/modules/<feature>/` | One feature: its module, controller, service, DTOs and entities | `austial g resource <name>` |
| `src/shared/guards/`, `pipes/`, `interceptors/`, `filters/`, `decorators/` | Cross-cutting pieces used by several modules | `austial g guard roles --shared` |
| `src/shared/services/` | Services several modules use (a mailer, a clock, an audit helper) | `austial g service mailer --shared` |
| `src/shared/dto/` | DTOs more than one module returns or accepts | by hand |
| `src/templates/` | Non-Python assets such as `email/welcome.html`. It is not a Python package | by hand |

Two rules keep the structure healthy as it grows:

- **Shared means two or more modules.** Start code inside the feature that uses it, and move it to `src/shared/` when a second
  module needs it. A feature never imports another feature's internals: it imports the other module and injects its exported provider.
- **A shared service is still a provider.** Generating `mailer_service.py` does not register it. List it in a module's `providers`
  (and `exports`) like any other provider.

Add more top-level folders as the app needs them, for example `src/config/` (typed settings), `src/database/`
(entities and migrations), `src/jobs/` or `src/events/`, and follow the same one-folder-per-concern rule.

<Callout type="info">
  **Existing projects keep working.** Projects created before this layout have a flat `src/app_module.py`. The CLI
  finds and patches whichever of `src/app/app_module.py` or `src/app_module.py` the project has, and `austial graph`,
  `austial repl` and `austial build` default to it. Move to the modular layout whenever you like: create `src/app/`, move
  `app_module.py`, `app_controller.py` and `app_service.py` into it, and update their imports.
</Callout>

## Running the app

```bash
uv run austial serve
```

is equivalent to:

```bash
uv run uvicorn src.main:app --reload
```

`austial serve` just locates your project root (by walking up for
`src/app/app_module.py`), puts it on `sys.path`, and calls
`uvicorn.run("src.main:app", reload=True)` for you.

## The bootstrap file

Every Austial app boots from `src/main.py`:

```python
from austial import AustialFactory
from austial.common.exceptions import AllExceptionsFilter
from austial.common.pipes import ValidationPipe

from .app.app_module import AppModule


def _build():
    app = AustialFactory.create(AppModule, title="my-app")
    app.use_global_pipes(ValidationPipe())
    app.use_global_filters(AllExceptionsFilter())
    app.enable_cors()
    return app


app = _build()


async def bootstrap() -> None:
    await app.listen(8000)
```

`AustialFactory.create(AppModule)` walks the `@Module` import graph starting
at `AppModule`, registers every provider/controller into one DI container,
wires up any middleware declared via `configure()`, and returns an
`AustialApplication` -- a thin wrapper around a real `fastapi.FastAPI`
instance. Because it's ASGI-callable itself (`app(scope, receive, send)`),
`uvicorn src.main:app` works directly.

## Developing without installing from PyPI

If you're contributing to the framework itself rather than consuming it,
point a new project at your local checkout instead:

```bash
git clone https://github.com/austial/austial-py
cd austial-py && uv sync
uv run austial new ../my-app --link .
```

`--link` adds an editable `[tool.uv.sources]` entry so `uv sync` resolves
`austial` from your local checkout instead of PyPI.
