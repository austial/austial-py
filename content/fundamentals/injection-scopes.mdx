# Injection Scopes

```python
from austial import Injectable, Scope
```

| Scope | Behavior |
|---|---|
| `Scope.DEFAULT` | **Singleton** (default). One instance shared across the whole application lifetime. |
| `Scope.TRANSIENT` | A brand-new instance is constructed every time the provider is resolved. |
| `Scope.REQUEST` | One instance **per request**, built on first use and discarded with the request. |

```python
@Injectable(scope=Scope.DEFAULT)     # same as plain @Injectable()
class CatsService:
    ...

@Injectable(scope=Scope.TRANSIENT)
class RequestIdGenerator:
    def __init__(self):
        self.id = uuid4()
```

Every place `RequestIdGenerator` is a constructor dependency gets its own
fresh instance; every place `CatsService` is a dependency shares the exact
same object.

```python
a = container.resolve(RequestIdGenerator)
b = container.resolve(RequestIdGenerator)
assert a is not b   # transient: different instances

x = container.resolve(CatsService)
y = container.resolve(CatsService)
assert x is y       # default: singleton
```

## Request scope

A request-scoped provider can safely hold per-request state as instance attributes. It is built the
first time something needs it during a request, shared by everything else in that request, and
dropped afterwards:

```python
@Injectable(scope=Scope.REQUEST)
class RequestContext:
    def __init__(self):
        self.request_id = str(uuid4())
        self.user = None


@Injectable()
class AuditService:
    def __init__(self, ctx: RequestContext):
        self.ctx = ctx          # the SAME RequestContext the controller and guards see


@Controller("cats")
class CatsController:
    def __init__(self, ctx: RequestContext, audit: AuditService):
        self.ctx, self.audit = ctx, audit

    @Get()
    async def find_all(self):
        assert self.audit.ctx is self.ctx
        return {"request_id": self.ctx.request_id}
```

### Scope bubbles up

Anything that depends on a request-scoped provider (directly or through other providers) is itself
resolved per request: `AuditService` above is `DEFAULT` scope on paper, but gets a fresh instance
every request. That includes **controllers, guards, pipes, interceptors and filters**, which are
then built per request instead of once at startup.

<Callout type="warning">
Per-request construction costs a little on every request. Prefer singletons, and reach for request
scope only when a provider genuinely needs per-request state.
</Callout>

### The `REQUEST` token

Inject the current Starlette `Request` itself with the `REQUEST` token. Any provider that depends on it
becomes request-scoped automatically:

```python
from austial import REQUEST, Inject, Injectable


@Injectable()
class ClientInfo:
    def __init__(self, request=Inject(REQUEST)):
        self.request = request

    @property
    def user_agent(self) -> str:
        return self.request.headers.get("user-agent", "")
```

### Durable providers

A request-scoped provider is built for every request. When many requests share the same *context* — all the requests of
one tenant — that is wasteful. A **durable** provider is built once per context key instead:

```python
from austial import ContextIdFactory, ContextIdStrategy, Injectable, Scope


@Injectable(scope=Scope.REQUEST, durable=True)
class TenantConnection:                      # one per tenant, not one per request
    def __init__(self):
        self.pool = open_pool()


class ByTenantHeader(ContextIdStrategy):
    def get_key(self, request):
        return request.headers.get("x-tenant")       # None -> no sharing for this request


ContextIdFactory.apply_strategy(ByTenantHeader())    # once, at startup
```

Requests with the same key get the same `TenantConnection`; other request-scoped providers are still per request. Without a
strategy (or when it returns `None`) a durable provider behaves like a normal request-scoped one. A durable provider must
not depend on non-durable request-scoped providers or on the `REQUEST` token: it would capture the first request's.

### Knowing who asked: `INQUIRER`

A provider that injects the `INQUIRER` token receives **the class that is asking for it** — and is therefore built once per
consumer, never shared. The classic use is a logger tagged with its owner:

```python
from austial import INQUIRER, Inject, Injectable


@Injectable()
class ContextLogger:
    def __init__(self, inquirer=Inject(INQUIRER)):
        self.context = inquirer.__name__            # "OrdersService", "UsersService", ...

@Injectable()
class OrdersService:
    def __init__(self, log: ContextLogger):         # its own ContextLogger("OrdersService")
        self.log = log
```

For a factory provider, add `INQUIRER` to its `inject` list. The consumers themselves stay singletons.

### Outside a request

Resolving a request-scoped provider with `app.get()` / `ModuleRef.get()` outside a request raises
`RequestScopeError`. Use `resolve()` with a context id instead, e.g. in a queue worker:

```python
from austial import ContextIdFactory

ctx = ContextIdFactory.create()
handler = app.resolve(ReportHandler, ctx)       # shares RequestContext within this context
```

See [Module Reference](/fundamentals/module-reference#resolving-request-scoped-providers).

## Singletons stay singletons

```python
first = container.resolve(CatsService)
second = container.resolve(CatsService)
assert first is second
```
