# Pipes

A pipe transforms or validates input data before it reaches a route handler.

## The `PipeTransform` interface

```python
from austial.common.pipes import ArgumentMetadata, PipeTransform


class TrimPipe(PipeTransform):
    def transform(self, value, metadata: ArgumentMetadata):
        return value.strip() if isinstance(value, str) else value
```

`ArgumentMetadata` describes the argument being processed:

```python
@dataclass
class ArgumentMetadata:
    type: Literal["body", "query", "param", "custom"]
    data: str | None       # the parameter name
    metatype: type | None  # the parameter's runtime type
```

## Built-in pipes

| Pipe | Does | On failure |
|---|---|---|
| `ParseIntPipe` | `"12"` → `12` (`"12.9"` → `12`, like `parseInt`) | `Validation failed (numeric string is expected)` |
| `ParseFloatPipe` | `"1.5"` → `1.5` | `Validation failed (numeric string is expected)` |
| `ParseBoolPipe` | `"true"`/`"false"` → `bool` | `Validation failed (boolean string is expected)` |
| `ParseUUIDPipe(version=None)` | checks the UUID format (and version); returns the string | `Validation failed (uuid v4 is expected)` |
| `ParseEnumPipe(MyEnum)` | `"red"` → `MyEnum.RED` | `Validation failed (enum string is expected)` |
| `ParseArrayPipe(items=None, separator=",")` | `"1,2,3"` → `[...]`; `items=int` (or `float`, `bool`, any pipe) parses each element | the item pipe's message |
| `DefaultValuePipe(default)` | substitutes `default` when the value is missing | — |
| `ParseFilePipe(validators=[...])` | validates an upload; see [File Upload](/techniques/file-upload) | `File is required`, … |

Attach them to **one parameter** by passing them after the name. Pipes on a `Param`, `Query` or
`Headers` parameter receive the *raw string*, so they do the parsing (FastAPI doesn't coerce it first):

```python
from austial import DefaultValuePipe, Param, ParseArrayPipe, ParseIntPipe, ParseUUIDPipe, Query


@Get(":id")
async def find_one(self, id: int = Param("id", ParseIntPipe)) -> Cat: ...


@Get()
async def find_all(
    self,
    page: int = Query("page", DefaultValuePipe(1), ParseIntPipe),     # pipes run left to right
    ids: list[int] = Query("ids", ParseArrayPipe(items=int)),         # ?ids=1,2,3
) -> list[Cat]: ...


@Get("owners/:id")
async def owner(self, id: str = Param("id", ParseUUIDPipe(version=4))): ...
```

Every parse pipe takes the same options:

```python
ParseIntPipe(
    error_http_status_code=406,                         # default 400
    exception_factory=lambda msg: MyValidationError(msg),   # wins over the status code
    optional=True,                                       # let None through instead of failing
)
```

You can also register them at any pipe scope (`@UsePipes`, `app.use_global_pipes`); they then run on every
argument, as in NestJS.

### Pipes can be classes, async, and injected

Pass a pipe **class** (`Param("id", MyPipe)`) and the container builds it, so it can take
constructor dependencies. `transform()` may be `async`:

```python
@Injectable()
class UserExistsPipe(PipeTransform):
    def __init__(self, users: UsersService):
        self.users = users

    async def transform(self, value, metadata: ArgumentMetadata):
        return await self.users.get_or_404(value)
```

`ArgumentMetadata.type` is `"param"`, `"query"` or `"body"` for helper-bound parameters (`"custom"`
otherwise), and `metatype` is the parameter's annotation when it is a class. Order: global → controller →
route pipes, then the parameter's own.

## The built-in `ValidationPipe`

```python
from austial.common.pipes import ValidationPipe

app.use_global_pipes(ValidationPipe())
```

`ValidationPipe` re-validates pydantic-model values (already parsed by
FastAPI against your type hints) and, on failure, raises a
`BadRequestException` shaped as:

```json
{
  "statusCode": 400,
  "message": ["field required: name"],
  "error": "Bad Request"
}
```

Since FastAPI already parses and type-checks request bodies against your
pydantic `BaseModel` DTOs before your handler runs, `ValidationPipe`'s main
job is normalizing *how* a validation failure is reported — into the same
error body shape every other exception produces, rather than FastAPI's
native `422` shape.

Every project scaffolded by `austial new` registers it globally in
`src/main.py` by default.

### `ValidationPipe` options

```python
ValidationPipe(
    whitelist=True,
    forbid_non_whitelisted=True,
    stop_at_first_error=True,
    error_http_status_code=422,
)
```

| Option | Effect |
|---|---|
| `whitelist` | Drop properties the DTO doesn't declare. Pydantic's default already ignores unknown fields while parsing; this also strips them from models declared `extra="allow"`. |
| `forbid_non_whitelisted` | Instead of dropping unknown **top-level** body properties, reject the request: `property role should not exist`. It reads the raw body, so in this mode `transform()` returns a coroutine (the router awaits it; `await` it yourself in a unit test). Field aliases count as known, and an embedded body (`Body(embed=True)`) is handled. |
| `stop_at_first_error` | Report only the first validation error. |
| `disable_error_messages` | Answer with the bare `Bad Request` instead of the list of errors. |
| `error_http_status_code` | Status for validation failures (default 400). |
| `exception_factory` | `errors: list[str] -> Exception`, to raise your own error type. |

NestJS's `transform` option has no equivalent: pydantic always hands the handler a typed model. Nested
objects are validated by pydantic itself; `forbid_non_whitelisted` checks the top level only.

`ArgumentMetadata` also carries the current `request`, for pipes that need it.

## Applying pipes

Globally (as above), or scoped to a controller/handler with `@UsePipes`:

```python
from austial import UsePipes


@Post()
@UsePipes(ValidationPipe())
async def create(self, dto: CreateCatDto = Body()) -> Cat:
    ...
```

## Binding pipes globally

`app.use_global_pipes(ValidationPipe())` takes an instance. To bind one **with dependency injection**,
register it under `APP_PIPE` in any module:
`{"provide": APP_PIPE, "useClass": MyPipe}`. See
[Guards: binding globally](/overview/guards#binding-guards-globally).

## Pipeline position

```
guards -> pipes -> interceptors (wrapping) -> handler -> exception filters
```

Pipes run after guards have authorized the request, but before interceptors
wrap the handler call — so a pipe can reject a request (by raising) before
any interceptor logic (like response transformation or timing) ever runs.
