# Guards

A guard determines whether a given request will be handled by the route
handler or not, based on certain conditions (permissions, roles, API keys,
ACLs, ...).

## The `CanActivate` interface

```python
from austial import CanActivate, ExecutionContext


class ApiKeyGuard(CanActivate):
    async def can_activate(self, context: ExecutionContext) -> bool:
        request = context.switch_to_http().get_request()
        return request.headers.get("x-api-key") == "expected-value"
```

`ExecutionContext` gives a guard access to the current request and the
handler/controller about to run:

```python
class ExecutionContext:
    def switch_to_http(self) -> "ExecutionContext": ...
    def get_request(self) -> Request
    def get_class(self) -> type      # the controller class
    def get_handler(self) -> Any     # the handler method
```

If `can_activate` returns a falsy value, Austial short-circuits the
pipeline and raises `ForbiddenException("Forbidden resource")` — a
`403`, formatted through the same [exception filter](/overview/exception-filters)
chain as everything else.

## Applying guards

```python
from austial import Controller, Get, UseGuards

from .api_key_guard import ApiKeyGuard


@Controller("health")
class HealthController:
    @Get("protected")
    @UseGuards(ApiKeyGuard)
    async def protected(self):
        return {"status": "ok"}
```

Stack `@UseGuards` on the controller class to protect every route in it,
or on a single handler for one route only — guards attached at multiple
levels combine.

```python
@Controller("cats")
@UseGuards(ApiKeyGuard)   # applies to every route below
class CatsController:
    ...
```

## Binding guards outside a controller

`ApiKeyGuard` itself is just an `@Injectable()`-free plain class here, but
nothing stops it from being a real provider with injected dependencies
(a `ConfigService` to read the expected key from, for example) — the
container resolves guard classes the same way it resolves controllers and
services.

```python
class ApiKeyGuard(CanActivate):
    def __init__(self, config: ConfigService):
        self._expected = config.get("API_KEY", "changeme")

    async def can_activate(self, context: ExecutionContext) -> bool:
        request = context.switch_to_http().get_request()
        return request.headers.get("x-api-key") == self._expected
```

## Binding guards globally

`app.use_global_guards(AuthGuard())` works, but you built that instance by hand, so it can't take
constructor dependencies. To bind a guard **globally with dependency injection**, register it as a provider
under the `APP_GUARD` token, in any module:

```python
from austial import APP_GUARD, Module


@Module(
    providers=[
        {"provide": APP_GUARD, "useClass": AuthGuard},      # AuthGuard(config: ConfigService) is injected
    ],
)
class AuthModule:
    pass
```

It applies to every route in the application, whichever module declared it. Register the token several times
to add several guards; `useClass`, `useValue`, `useFactory` and `useExisting` all work. Guards from
`use_global_guards` run first, then the `APP_GUARD` ones in registration order, then controller and route guards.

The same pattern binds the other three pipeline stages: `APP_PIPE`, `APP_INTERCEPTOR` and `APP_FILTER`.

```python
providers=[
    {"provide": APP_PIPE, "useFactory": lambda: ValidationPipe(whitelist=True), "inject": []},
    {"provide": APP_INTERCEPTOR, "useClass": LoggingInterceptor},
    {"provide": APP_FILTER, "useClass": DatabaseErrorFilter},
]
```

A global component that depends on a request-scoped provider is built per request, like any other.

## Pipeline position

```
guards -> pipes -> interceptors (wrapping) -> handler -> exception filters
```

Guards run **first** — before any pipe validates input or any interceptor
wraps the call — so unauthorized requests never reach handler logic (or
pay the cost of body validation).
