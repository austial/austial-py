# Authentication

`austial.auth` provides authentication primitives — password hashing, JWT
access tokens, TOTP for multi-factor authentication, a refresh-token store
contract, and an `AuthGuard` that verifies bearer tokens on every request.

The framework does not define your user model or the persistence layer.
Instead it gives you strategies and a guard; you wire them together against
your own user entity. This mirrors the `@nestjs/passport` + `@nestjs/jwt`
split.

## Setup

```python
from austial import Module
from austial.auth import AuthConfig, AuthModule


@Module(
    imports=[
        AuthModule.for_root(
            AuthConfig(
                jwt_secret="a-real-secret-at-least-32-characters",
                issuer="fundos",
            )
        ),
    ],
)
class AppModule:
    pass
```

`AuthConfig` accepts:

- `jwt_secret` — HS256 signing secret (at least 32 characters; the strategy
  fails at startup otherwise, per OWASP ASVS V6).
- `issuer` — the `iss` claim; typically your app name.
- `algorithm` — `"HS256"` (default) or `"RS256"`.
- `access_ttl` — access-token lifetime (default 15 minutes).
- `refresh_ttl` — refresh-token lifetime (default 14 days).
- `totp_digits`, `totp_window` — TOTP configuration.

`AuthModule` is registered `@Global()` by default so any module can inject
`JwtStrategy`, `TotpStrategy`, `PasswordHasher`, `AuthService` and
`AuthGuard` without a re-import.

## Password hashing (Argon2id)

```python
from austial import Injectable
from austial.auth import Argon2Hasher


@Injectable()
class UsersService:
    def __init__(self, hasher: Argon2Hasher):
        self._hasher = hasher

    def register(self, password: str) -> str:
        return self._hasher.hash(password)  # PHC-string, safe to persist

    def check(self, password: str, stored: str) -> None:
        self._hasher.verify(password, stored)  # raises PasswordVerificationError
        if self._hasher.needs_rehash(stored):
            # opportunistically upgrade on next successful login
            ...
```

Defaults are calibrated to OWASP's 2024 interactive-login profile
(≥19 MiB memory, 2 iterations, 1 lane). Override in the constructor if
your infrastructure allows heavier parameters.

## JWT access tokens

```python
from austial.auth import JwtStrategy


def sign_login(jwt: JwtStrategy, user_id: str, tenant_id: str) -> str:
    return jwt.sign(user_id, claims={"tenant": tenant_id, "roles": ["ops"]})


def whoami(jwt: JwtStrategy, token: str) -> str:
    payload = jwt.verify(token)   # raises TokenExpiredError / InvalidTokenError
    return payload.subject
```

Tokens carry `iss`, `iat`, `exp` and `jti` in addition to your application
claims. The `jti` gives you a hook for per-token revocation without changing
the wire format.

## TOTP multi-factor authentication

```python
from austial.auth import TotpStrategy


def enrol(totp: TotpStrategy, account: str) -> tuple[str, str, list[str]]:
    secret = totp.generate_secret()
    uri = totp.provisioning_uri(secret, account)  # QR-code payload
    recovery = totp.generate_recovery_codes()
    return secret, uri, recovery


def check(totp: TotpStrategy, secret: str, code: str) -> bool:
    return totp.verify(secret, code)  # one-window drift allowed
```

Persist the secret against the user record. Persist recovery codes
**hashed** (via `Argon2Hasher`) so a database leak does not compromise them.

## Refresh tokens

Refresh tokens are opaque strings (not JWTs) that the store persists so
they can be revoked. Framework ships an `InMemoryRefreshTokenStore` for
tests and local dev; product code supplies a persistent implementation
against its ORM:

```python
from austial.auth import RefreshTokenStore

# supply a persistent implementation
AuthModule.for_root(config, refresh_token_store=MyOrmRefreshTokenStore())
```

Pass a **class**, not just an instance, when the store itself needs DI (a repository, another
service): `for_root` registers it with `useClass`, so the container resolves its own constructor
dependencies once the app boots, instead of you having to build it by hand before the DI container
exists. `password_hasher` accepts the same class-or-instance shape. An instance (as above) still
works for a store with no dependencies of its own.

`AuthService` orchestrates `issue_tokens`, `refresh` and `logout`:

```python
from austial.auth import AuthService


class LoginController:
    def __init__(self, auth: AuthService, users: UsersService):
        self._auth = auth
        self._users = users

    async def login(self, dto):
        user = self._users.by_email(dto.email)
        self._auth.verify_password(dto.password, user.password_hash)
        self._auth.require_mfa(user.totp_secret, dto.totp_code)
        return await self._auth.issue_tokens(user.id, claims={"tenant": user.tenant_id})
```

Rotation on refresh is atomic (the old refresh token is revoked as the new
one is issued). `logout_everywhere(subject)` revokes every active refresh
token for a user — call it on password change, MFA re-enrolment, or an
admin action.

`AuthService.refresh`'s `claims` argument also accepts a **callable** — `(record:
RefreshTokenRecord) -> dict | Awaitable[dict]` — instead of a fixed dict, for when the new access
token's claims depend on the rotated token itself (its `session_id`, or the subject's *current*
tenant/roles, which may have changed since the refresh token was issued):

```python
async def claims_for(record):
    session = await sessions.get_active(record.session_id)
    membership = await memberships.find_one_by({"tenant_id": session.tenant_id, "user_id": record.subject})
    return {"tenant": session.tenant_id, "roles": [membership.role], "sid": session.id}

pair = await auth.refresh(opaque_refresh_token, claims=claims_for)
```

A `PasswordVerificationError`/`AuthenticationError` (or anything else) raised inside the callable
propagates to the caller of `refresh()` as-is.

## Guarding routes

```python
from austial import Controller, Get, UseGuards
from austial.auth import AuthGuard, CurrentUser, Public


@Controller("/me")
@UseGuards(AuthGuard)
class MeController:
    @Get()
    def me(self, user=CurrentUser()):
        return {"id": user.subject, "claims": user.claims}

    @Public()
    @Get("/robots.txt")
    def robots(self):
        return "User-agent: *\nDisallow:"
```

`AuthGuard` reads the `Authorization: Bearer <jwt>` header, verifies it with
`JwtStrategy`, and populates `request.state.user` with an `AuthPrincipal`.
`CurrentUser()` retrieves the principal in a handler parameter — resolved
*after* every guard for the route has run (including a global one registered
via `app.use_global_guards(AuthGuard, ...)`, which is the common case: nothing
above requires `@UseGuards(AuthGuard)` on every controller). `@Public()` skips
the guard for a specific route or an entire controller, and `CurrentUser()`
then resolves to `None`.

Under the hood `CurrentUser()` is `austial.common.FromRequestState("user")`: a
handler parameter bound to `request.state.<attribute>`, read only once the
router's guard loop has finished (a plain FastAPI `Depends` would resolve
before that loop runs, over an empty `request.state`, however the guard was
registered). Any guard that publishes something onto `request.state` — a
product `TenantGuard` subclass, a session guard — can use the same helper for
its own param:

```python
from austial.common import FromRequestState

def CurrentTenant() -> Any:
    return FromRequestState("tenant", default=None)
```

To layer additional checks (session freshness, per-tenant claims) subclass
`AuthGuard` and override `after_verify`.

## Custom strategies (Passport-style)

For schemes `AuthGuard` doesn't cover (API keys, basic auth, signed webhooks, sessions), write a strategy and guard routes
with it, as with `@nestjs/passport`:

```python
from austial.auth import AuthenticationError, AuthStrategy, CurrentUser, StrategyGuard

@Injectable()
class ApiKeyStrategy(AuthStrategy):
    name = "api-key"

    def __init__(self, keys: KeysService):
        self.keys = keys

    async def validate(self, request):
        owner = await self.keys.owner_of(request.headers.get("x-api-key", ""))
        if owner is None:
            raise AuthenticationError("invalid API key")
        return owner                                   # lands in request.state.user

@Module(providers=[ApiKeyStrategy, KeysService])
class KeysModule: ...

@Controller("reports")
@UseGuards(StrategyGuard("jwt", "api-key"))            # a bearer token OR an API key, tried in order
class ReportsController:
    @Get()
    def list(self, user=CurrentUser()): ...
```

`StrategyGuard(*names)` accepts a request when any named strategy validates it; if none does, the first strategy's error
(`401`) is raised. Strategies are discovered from every module's providers. `"jwt"` (`JwtBearerStrategy`) is provided by
`AuthModule`. `@Public` routes skip the guard. This is not Passport itself: there is no adapter for Passport's Node strategies; implement
`validate` against the provider's library (for OAuth, see below).

## Social login (OAuth 2.0 / OpenID Connect)

`OAuth2Provider` implements the authorization-code flow with PKCE; you own the routes and the session. Presets exist
for `GoogleOAuth`, `GitHubOAuth` and `MicrosoftOAuth`, and `OAuth2Provider.from_oidc_discovery(issuer, ...)` configures any
OIDC provider (Auth0, Okta, Keycloak...) from its `/.well-known/openid-configuration`.

```python
from austial.auth import GoogleOAuth, verify_state

google = GoogleOAuth(client_id=..., client_secret=..., redirect_uri="https://app.example.com/auth/google/callback")


@Controller("auth/google")
class GoogleAuthController:
    @Get()
    async def start(self, response: Res):
        request = google.authorization_url()            # fresh state + PKCE verifier
        # `sign`/`unsign` stand for whatever signed-cookie or session mechanism you use
        response.set_cookie("oauth", sign({"s": request.state, "v": request.code_verifier}), httponly=True, secure=True)
        return RedirectResponse(request.url)

    @Get("callback")
    async def callback(self, code: str, state: str, oauth: str = Cookies("oauth")):
        saved = unsign(oauth)
        verify_state(saved["s"], state)                  # constant-time CSRF check; raises OAuthError
        tokens = await google.exchange_code(code, code_verifier=saved["v"])
        profile = await google.fetch_user(tokens.access_token)         # {"email": ..., "name": ...}
        user = await self.users.find_or_create(profile["email"])
        return await self.auth.issue_tokens(user.id)     # your own JWT pair (see Refresh tokens)
```

| Call | Does |
|---|---|
| `authorization_url(state=None, scopes=None)` | An `AuthorizationRequest(url, state, code_verifier)`. Keep `state` and `code_verifier`. |
| `await exchange_code(code, code_verifier=)` | `OAuthTokens(access_token, refresh_token, expires_in, id_token, ...)`. |
| `await refresh(refresh_token)` | New tokens. |
| `await fetch_user(access_token)` | The userinfo endpoint's JSON. |
| `generate_state()` / `verify_state(expected, received)` | Random state / constant-time comparison. |

### Verifying ID tokens (OpenID Connect)

```python
request = provider.authorization_url()                 # adds a `nonce` when the scopes include "openid"
# keep request.state, request.code_verifier and request.nonce (signed cookie / session)
tokens = await provider.exchange_code(code, code_verifier=verifier)
claims = await provider.verify_id_token(tokens.id_token, nonce=saved_nonce)   # raises OAuthError
```

`verify_id_token` checks the signature against the provider's JWKS (cached for `jwks_ttl`, re-fetched once when the token's `kid` is
unknown, which covers key rotation), restricts the algorithm to `id_token_algorithms` (default `("RS256",)`, so `alg: none` and HMAC
confusion fail), `aud` equals your client id, `iss` matches `issuer`, `exp`/`iat` with 60 s of clock skew, and the `nonce` if given.
The Google preset, and discovery (`from_oidc_discovery`), fill in `jwks_uri` and `issuer`; set them yourself on a custom provider. The
Microsoft preset does not pin `iss` for the multi-tenant endpoints (`common`, `organizations`, `consumers`), where the issuer varies per
tenant: check the `tid` claim yourself. Requires `pyjwt[crypto]`, which `austial-auth` installs.

<Callout type="warning">
Storing `state`, the PKCE verifier and the `nonce` (a signed, `httponly` cookie or your session) is your responsibility; never skip
`verify_state`, and never trust an ID token you did not pass through `verify_id_token`.
</Callout>

## Errors

All auth failures extend `UnauthorizedException` (mapping to `401`), with
sub-types for programmatic handling:

- `AuthenticationError` — generic parent.
- `InvalidTokenError` — malformed, tampered, wrong issuer.
- `TokenExpiredError` — `exp` in the past.
- `MfaRequiredError` — password OK but MFA still pending.

Never surface which failure occurred to the client verbatim; log the sub-type
and return a generic `401` message to callers.

## Security posture (OWASP ASVS L2)

- V2 auth: Argon2id with OWASP-2024 parameters; password verification runs
  in constant time via `argon2-cffi`.
- V3 session: short-lived (15-minute) access tokens, opaque rotating refresh
  tokens with server-side revocation and per-user bulk revoke.
- V6 crypto: minimum 32-character HS256 secret enforced at startup; RS256
  is a one-line change.
- V13 API: bearer authentication only; guard verifies before every handler
  unless explicitly `@Public`.
